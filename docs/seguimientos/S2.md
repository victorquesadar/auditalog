## 4. Decisiones técnicas tomadas

| Decisión | Alternativa descartada | Motivo |
|---|---|---|
| **Pydantic + `$jsonSchema`** en vez de solo Pydantic | Validar solo en la API | El worker también escribe en Mongo; validar en la BD cubre ese camino sin duplicar lógica |
| **Consumer group** (`XREADGROUP`) en vez de `XREAD` plano | — | Deja preparado el escalado a múltiples workers en S3 |
| **Caché del dashboard con TTL 30s** | Calcular en cada request | Permite medir "con/sin caché" en S3 como parte de los 3 benchmarks |
| **Loghub con fallback sintético** | Solo Loghub real | Si falla el repo público, el script sigue andando y el grupo puede trabajar sin internet |
| **Exportador SQLite ya en S2** | Dejarlo para S4 | Cerró el loop de evidencia completo; permite demostrar el valor diferencial antes |
| **Transacción multi-insert en la carga** | `insert_many` suelto | Si el cluster soporta replica set (Atlas sí), queda atómico; cae a modo normal en standalone |
